# 关卡前置学习流程分期实现文档
## 实施状态与下一步（2026-08-03）

### 已完成

- 第 101 关已具备三页剧情开场。
- 第 401 关已具备三页二进制剧情，并在剧情后进入实物槽位训练。
- 二进制训练已使用最上方四个真实槽位，左到右为物理槽位 `6 / 4 / 2 / 0`，权重为 `8 / 4 / 2 / 1`；空槽为 `0`，任意积木占位为 `1`。
- 活动页仅显示四个槽位及其 `0/1` 状态，支持三道题 `{4, 5, 2}`、中键推进、右键跳过和顶行 LED 高亮。
- 第 403 关已具备三页半加器剧情和三题训练。实体槽位采用两列两行：左列 `A / B` 为槽位 `6 / 7`，右列 `个位 / 进位` 为槽位 `0 / 1`。
- 第 501 关已具备三页三路求和剧情和三题奇偶训练。实体槽位采用左列 `A / B / 进位输入`，分别为槽位 `6 / 7 / 8`；训练只判断个位是否为 `1`，因此放 `1` 或 `3` 块积木都能得到 `1`，放 `0` 或 `2` 块得到 `0`。
- 第 504 关“图灵主控”已具备三页全加器剧情和三题训练。实体槽位采用左三右二：左列 `A / B / 进位输入` 为槽位 `6 / 7 / 8`，右列 `个位 / 进位输出` 为槽位 `0 / 1`。
- 训练框内的 `0/1` 与角色文字统一使用白色，避免与蓝色、绿色槽位背景混淆。
- 活动期间不启动正式判题；为读取积木状态，底板 I2C 以只读方式继续扫描，积木 OLED 不显示图案。儿童主动长按右键时可请求远端助教，活动状态会随请求上传，后端与固件都会拒绝端口高亮类工具。

## 目标

为积木电路课程建立可扩展的关卡前置学习流程：剧情对话建立任务情境，概念小游戏帮助理解抽象知识，正式游玩负责实际搭电路。第 101 关先实现剧情开场；二进制小游戏和其语音助教随后独立接入。

## 总体架构

学习流程由固件中的关卡学习内容配置驱动。每个关卡可配置零个或多个剧情页、一个可选的概念活动，以及活动结束后的桥接文案。页面状态机采用：`DETAIL -> INTRO -> LEARNING_ACTIVITY -> PLAY`；不配置活动的关卡从 `INTRO` 直接进入 `PLAY`。

`INTRO` 不属于真实游玩状态：不采集电路、不判题、不创建语音 Session。`LEARNING_ACTIVITY` 和 `PLAY` 可共享 Session；活动状态通过可选顶层 `learning_activity` 请求字段传给远程助教，原有 `tuco_circuit_v2` 快照格式保持不变。

## 第二期：通用概念小游戏框架

### 范围

- 用 `learning_activity` 模块保存活动类型、题目、槽位权重、当前 0/1 状态、完成状态和桥接文案。
- 增加 `UI_PAGE_LEARNING_ACTIVITY`，先实现二进制槽位控件：摇杆选槽，中键切换 0/1。
- 半加器章节使用固定 3 题：认识 1/2/4、组合目标数、将十进制 2 写为二进制 10。
- 活动只在玩家主动离开、完成或跳过时转入正式游玩；不根据错误次数自动提示。

### 固件边界

- `level_intro` 演进为只读内容配置，活动运行状态独立存放，避免 UI 和内容数据相互耦合。
- 活动页不启动电路判题；但活动页可启用语音输入。
- 复玩策略默认是每次可跳过；是否写入“已完成活动”进度由后续产品决定。

### 验收

1. 题目目标与槽位状态可由纯逻辑自检覆盖。
2. 活动页不触发电路判题或端口高亮。
3. 完成目标后显示正确的二进制结果和关卡桥接语。

## 第三期：活动态远程语音助教

### 请求协议

在保留 `session_id`、`user_text`、`circuit_snapshot` 的基础上，可选增加：

    learning_activity: {
      kind: "binary_slots",
      stage: "practice",
      round_index: 2,
      round_total: 3,
      target_decimal: 13,
      slot_weights: [8, 4, 2, 1],
      slot_bits: [1, 1, 0, 1],
      current_decimal: 13,
      solved: true
    }

### 固件改动

- 在 `remote_assistant` 构造请求时附加活动状态。
- 将语音 Session 生命周期从“仅游玩页”扩展为“活动页或游玩页”；从活动进入游玩时不能重建 Session。
- 活动页仅支持右键长按主动提问；不主动发起模型请求。
- 远程工具响应在活动页必须拒绝执行，作为固件侧保护。

### 后端改动

- `CircuitCoachDecisionRequest` 显式解析可选 `learning_activity`，不能依赖忽略未知字段。
- 提示词组装优先处理活动态：解释当前题目和槽位；禁止“先放输入输出”提醒；不向模型提供端口高亮工具。
- 玩家明确要求答案时才报告完整 0/1；其它情况按差值和槽位权重逐步引导。
- 会话历史跨活动页与正式游玩保存，离开整个关卡流程后关闭。

### 验收

1. 活动请求不会被空电路快照的缺积木规则劫持。
2. 活动响应无 `highlight_ports` 或 `highlight_empty_slot` 工具调用。
3. 进入正式游玩后恢复既有积木、接线与端口高亮教学规则。
4. 语音只在孩子主动长按右键时请求模型。

## 第四期：测试、测评与部署

- 固件：内容数据自检、活动状态自检、Session 迁移自检、字形覆盖检查、ESP-IDF 增量构建和实机按键验证。
- 后端：请求模型、活动提示词优先级、禁工具、显式答案策略和会话连续性单测。
- 并发测评：覆盖未完成、接近答案、完成、问为什么、要求直接答案与闲聊六种活动状态。
- 部署：后端先在本地和并发测评验证，再部署云端；最后烧录固件并确认云端日志中接收到活动状态。

## 风险控制

- 新剧情文案必须重新生成 16 px 和 24 px 中文字库，否则可能出现方块字。
- 现有 UI 会预创建全部 LVGL 页面；活动页应控制对象数量并在实机检查堆余量。
- 第一阶段不改 `sdkconfig`、后端地址、密钥或电路快照，避免与当前稳定链路耦合。
- `.superpowers/` 下的设计原型不纳入固件提交。
